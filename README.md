# STEEL BODY

운동 기록 PWA. 운동·인바디를 기록하면 EXP와 티켓이 쌓이고, 그 티켓으로 파칭코·사다리·미니게임을 돌려 레벨을 올린다.

- **Frontend** `frontend/` — React 18 + Vite + Zustand + Recharts
- **Backend** `backend/` — Node.js + Express + SQLite, JWT 인증
- **배포** Render (`render.yaml`)

```bash
cd frontend && npm run dev     # http://localhost:5173
cd backend  && npm start       # http://localhost:4000
```

개발 편의 파라미터(개발 빌드 전용): `?level=N` `?level=max` `?tickets=N` `?reset=1`

## 레벨 체계

세 단계가 위로 쌓인다. 각 단계는 앞 단계를 다 채워야 열리고, 열리면 **0부터 다시 시작**한다.

| 단계 | 범위 | 화폐 | 여는 조건 |
|---|---|---|---|
| **일반** | LV 0 ~ 149 (30티어 × 5레벨) | EXP | 처음부터 |
| **초월** | 0 ~ 100 (10등급) | EXP · 1레벨당 80조 | LV 149 도달 |
| **개벽** | 0 ~ 100 (10등급) | ⚡ **울트라 레전드 EXP** · 1레벨당 80조 | 초월 100 |

누적 EXP 상한은 **8,999조**다. 일반 150레벨 + 초월 100레벨이 JS 안전 정수(2^53 = 9,007조)를 거의 다 쓰기 때문에, 개벽은 아예 다른 값(울트라 레전드 EXP)으로 센다. 한 숫자로 계속 세면 끝자리가 뭉개진다.

## 티켓 · 게임

```
운동/인바디 기록 ──┐
원판 피하기      ──┴─→ 🎫 일반 티켓 ──┬─→ 파칭코 (1장)      ─┐
                                      ├─→ 사다리 (100장)    ─┴─→ EXP
                                      └─→ 교환소 (200장)
                                              ↓
                                        🎟️ 울트라 티켓 ──→ 울트라 레전드 파칭코 (1장) ──→ ⚡ UL EXP
```

- 일반 티켓 보유 상한 150장 (넘으면 소멸, 안내 뜸)
- **티켓도 판 수도 "시작하는 순간" 확정 차감한다.** 연출이 끝날 때 차감하면 결과를 미리 보고 새로고침해서 무를 수 있다. 대신 연출 중 이탈하면 보상을 반드시 정산한다 (언마운트 + `pagehide` 양쪽)
- 원판 피하기의 **울트라 무한(∞)** 을 주우면 티켓이 영구히 안 닳는다 (지갑에 큰 수를 넣는 게 아니라 차감을 멈추는 방식)
- 확률표는 언제나 **운영 확률**을 보여준다. 개발 빌드에서 부풀린 값(`devWeight`)은 경고와 함께 따로 표시한다

## 2026-08-20

**공지사항 기능 제거 — 안 쓰는 기능이었다**

없애기로 결정했다. 그 자리(`더보기` 안)에는 나중에 새 페이지를 만들어 붙인다 — **시안을 따로 만들어 확인한 뒤** 연결하는 순서로 간다. 오늘은 제거만 했다.

- **지운 파일 6개, 1,897줄** — `pages/NoticePage.jsx`(454) · `components/AiNoticeWriter.jsx`(718) · `components/NoticeBanner.jsx`(140) · `components/admin/NoticeAdmin.jsx`(208) · `data/aiNoticeTemplates.js`(261) · `data/notices.js`(116)
- **물려 있던 곳** — `App.jsx`(lazy import + `/notice` 라우트) · `TabBar.jsx`(더보기 항목) · `HomePage.jsx`(배너 · 팝업 · 안 읽은 공지 큐 · 검색 항목) · `AdminPage.jsx`(`공지사항 관리` · `AI 공지` 탭)
- `AdminPage` 의 기본 탭이 `notice` 였다. `maint`(점검 스케줄)로 바꿨다 — 안 그러면 관리자 페이지가 빈 화면으로 열린다
- `MaintAdmin` 이 점검을 걸 때마다 `ironlog_maint_notices` 에 공지를 만들어 저장하고 있었는데, **읽는 쪽이 아무 데도 없었다.** 공지 페이지가 사라지면 영영 안 읽히므로 그 블록(16줄)을 지웠다. 점검 화면에 뜨는 안내는 이것과 무관하게 `MaintenanceScreen` 이 따로 그린다
- 안 쓰게 된 import 도 같이 정리했다 (`HomePage` 의 `useCallback`, `MaintAdmin` 의 `readLS`)
- 옛 `/notice` 북마크는 `App.jsx` 의 `path="*"` 폴백이 받아서 홈으로 보낸다. 따로 리다이렉트를 두지 않았다

**백엔드는 남겼다.** `routes/notices.js`(113줄) 와 `db.js` 의 notices 테이블은 "레코드 목록 + 관리자 조회" 라는 모양이 다음에 만들 **버그 제보함**과 같다. 새로 만드는 것보다 이걸 제보용으로 돌리는 게 싸다. 쓰기는 전부 `adminAuth` 뒤에 있어 그대로 둬도 열려 있지 않다.

- 확인: 운영 빌드 통과. 헤드리스 Chrome 으로 홈 진입(로그인 유지) · 화면 어디에도 `공지` 없음 · `/notice` → `/home` 폴백 · `더보기` 여섯 항목(미니게임 · 홈트레이닝 · 운동 검색 · 측정 시스템 · 히스토리 · 관리자) · 관리자 탭 5개로 줄고 `점검 스케줄` 이 기본으로 열림 · **콘솔 에러 0건**

**공지 자리에 들어갈 새 페이지 — 시안 5종을 만들고 D안으로 정했다**

앱에는 **아직 붙이지 않았다.** 탭에도 검색에도 이름이 없고 주소로만 열린다.
`import.meta.env.DEV` 로 갈라 두어 운영 번들에는 통째로 담기지 않는다 (빌드 후 `dist` 에 문자열 0건 확인).

- `/preview` 목록 · `homepage`(A 소개+제보함) · `-b`(깔끔) · `-c`(대시보드) · **`-d`(문장형 ← 결정)** · `-e`(타일) · `/preview/report`(제보함) · `/preview/notices`(공지함)
- **고른 기준은 "이 자리에 놓였을 때"** 다. C·E 는 잘 만들수록 홈 탭과 하는 일이 겹친다. D 의 약점("훑기보다 읽어야 한다")은 매일 여는 화면일 때 값을 치르는데, 이 페이지는 `더보기` 안이라 그 값을 거의 안 낸다
- 숫자는 손으로 적지 않는다 — 레벨 상한 · 등급 이름 · 등급 수 · 티켓 규칙 · 교환비 · 앱 버전을 전부 실제 상수와 등급표, `package.json` 에서 읽는다. **일반 만렙 등급을 `신화` 로 적어뒀었는데 실제로는 `이름 없는 것` 이었다** — 손으로 적으면 이렇게 어긋난다

**제보함 — 유형을 고르면 그 다음이 달라진다**

셋을 같은 폼으로 받으면 버그는 정보가 모자라고 문의는 쓸데없이 길어진다.

- **버그** — 어느 화면인지 · 다시 해도 그런지(매번/가끔/한 번만)를 묻고 기기 정보를 기본으로 붙인다. 재현할 수 있어야 고친다
- **문의** — 제목만 있으면 된다. 내용 칸은 3줄로 줄고 기기 정보도 안 붙인다
- **건의** — `지금은 어떻게 하고 계신가요`(방법이 없다/불편하게 돌려서 한다/없어도 된다)를 묻는다. 대안이 있는지가 순서를 정한다
- **막는 것은 유형과 제목뿐이다.** 처음엔 화면·빈도·내용 10자까지 넷을 다 요구했는데, 제목을 쓰고도 버튼이 죽어 있다는 지적을 받았다. 못 보내게 막는 것보다 부실하게라도 받아서 되묻는 편이 낫다. 나머지는 `…까지 적어주시면 더 빨리 찾습니다` 로 회색 안내만 한다
- 지우기 두 곳 — 쓰던 것 비우기(뭔가 썼을 때만 나온다)와 보낸 제보 지우기. 카드 누르기가 접기/펼치기라 **지우기는 한 번 더 묻는다**
- 목록에 꼬리표가 붙는다 (버그는 `미니게임` `매번 그래요`, 건의는 `불편하게 돌려서 해요`)

**공지는 사람이 쓰지 않는다**

사람이 적으면 두 가지가 어긋난다 — 적는 걸 잊어서 목록이 비거나, 적어놓고 실제와 달라지거나.

- `scripts/gen-changelog.mjs` 가 **git 커밋에서 `feat`·`fix`·`perf` 만** 뽑아 `src/data/changelog.json` 을 만든다. `chore`·`docs`·`refactor` 와 `(dev)` 범위는 화면이 안 바뀌므로 뺀다
- `predev`·`prebuild` 로 **자동 실행**된다. 커밋하면 목록이 알아서 따라온다
- **커밋 본문(`%b`)이 화면에서 펼쳐 보는 세부 내용이 된다.** 이미 커밋마다 자세히 적고 있었으니 따로 쓸 것이 없다
- 커밋 제목으로 설명이 안 되는 것, 미리 알려야 하는 것은 `src/data/notices.json` 에 손으로 적는다. `pinned: true` 면 날짜와 상관없이 맨 위
- 둘은 `pages/preview/feed.jsx` 에서 한 목록으로 합쳐진다 — 공지는 오렌지, 커밋에서 온 것은 회색. 같은 날이면 공지가 먼저다 (커밋은 무슨 일이 있었는지를, 공지는 그게 무슨 뜻인지를 말한다)
- git 이 없거나 저장소가 아니어도 **스크립트는 실패로 끝나지 않는다.** 있던 json 을 두고 조용히 빠진다 — 빌드를 막을 이유가 없다
- **공지함**(`/preview/notices`)에 전부 있다. 종류로 거르고 날짜별로 묶는다. 홈페이지의 `최근 바뀐 것` 여섯 줄과 **같은 목록을 본다**

**남은 것** — 제보함 서버 연결(백엔드 `notices` 테이블 전환) · 탭 이름 결정 · 공지함 라벨(`제거` 가 `새 기능` 으로 뜬다) · 점검 예정 실제 렌더 확인 · FAQ 문답 검토. 붙이는 것은 8/24(월) 예정.

- `styles/globals.css` 의 `[data-theme="light"]` 블록 47줄과, 반응형 미디어쿼리에 남아 있던 `[data-theme="light"]` 셀렉터를 지웠다. `:root, [data-theme="dark"]` 로 갈라져 있던 것도 `:root` 하나로 합쳤다

**저장소를 막아둔 브라우저에서 앱이 통째로 흰 화면이 되던 것**

크롬의 "모든 쿠키 차단" 같은 설정에서는 `localStorage` 를 **읽기만 해도** `SecurityError` 를 던진다. 파칭코 계열은 예전에 `readLS`/`saveLS` 로 막아뒀지만 나머지 앱은 그대로였고(`docs/BUGS.md` 에 남은 범위로 적혀 있던 것), 실제로 재현해 보니 `data/admin.js` 의 `isAdmin()` 이 `MaintenanceScreen` **렌더 중에** 던져서 앱 전체가 죽었다. 이건 사용자가 로그인조차 못 하는 상태다.

- `data/safeStorage.js` 를 새로 만들어 `readLS`·`saveLS`·`removeLS`·`readInt` 를 옮기고 `readCookies` 를 더했다. `pachinkoData` 는 기존 import 경로가 안 깨지게 다시 내보낸다 — 인증·API 계층이 파칭코 상품표를 끌어오면 안 되므로 파일을 나눴다
- **src 전체의 raw `localStorage` 호출 140곳을 전부 안전 래퍼로 바꿨다** (0곳 남음). 특히 크래시 경로 셋:
  - `store/authStore.js` — 모듈 로드 시점에 읽는다. 여기서 던지면 import 단계에서 흰 화면
  - `api/client.js` — 요청 인터셉터. 던지면 모든 API 호출이 죽는다
  - `components/MaintenanceScreen.jsx` + `data/admin.js` — App 전체를 감싼다. 실제 범인
- `index.html` 의 테마 인라인 스크립트도 `try/catch` 로 감쌌다 — `<head>` 에서 동기로 도는 첫 코드다
- 개발 도구(`autoLogin`·`setLevel`·`setTickets`)도 같이 바꿨다. 앱보다 먼저 도는 코드라 여기서 던지면 개발 중에는 이 시나리오를 테스트할 수조차 없었다

검증 — 헤드리스 Chrome 에서 `localStorage` 게터가 `SecurityError` 를 던지도록 바꿔치기하고 접속:
- 고치기 전: 본문 **0자**, 흰 화면, uncaught 3건
- 고친 뒤: 본문 **1,075자**, 쿠키로 로그인 유지, **uncaught 0건**
- 정상 상태 회귀도 확인 — 로그인 · `/api/health` 200 · 파칭코 1판(티켓 9,999,999 → 9,999,998, 결과 표시) · 미니게임 캔버스 · 기록 페이지 모두 정상, 콘솔 에러 없음

**교환소 — 무한 티켓일 때 `최대` 꾹 누르기가 멈추지 않던 것**

∞ 를 얻으면 일반 티켓이 닳지 않으므로 "지갑이 빌 때까지"가 영원히 오지 않는다. 누르고 있는 동안 초당 수만 장의 울트라 티켓이 찍혀 나왔다. 무한이면 한 번 바꾸고 멈춘다 — 한 번에 바꿀 수 있는 최대치는 이미 나갔으니 더 누를 이유가 없다.


**버그 · 최적화 훑기**

`일반 파칭코 확률표도 개발 확률을 진짜처럼 보여주고 있었다` — 사다리와 똑같이 `if (DEV) miss.weight = 30000` 으로 덮어써서, 표가 꽝을 **5.9%** 로 띄웠다(진짜 52.9%). 판당 평균(`EXPECTED_EXP`)도 개발 기준이었다. `prizeWeight` · `PRIZE_WEIGHT_TOTAL_PROD` · `PRIZE_HAS_DEV_WEIGHTS` 로 분리하고 경고 배너를 붙였다. 이로써 원판·울트라·사다리·파칭코 네 표가 모두 같은 규격이 됐다.

`캔버스 배경 그라디언트를 프레임마다 새로 만들고 있었다` — 높이에만 의존하는데 60fps 루프 안에 있어 초당 60개를 만들어 버렸다. 크기가 바뀔 때만 다시 만들도록 `bgRef` 에 캐시했다.

`추첨할 때마다 가중치 합계를 다시 더했다` — `drawPrize` · `drawLadderPrize` · `drawUlPrize` 셋 다 매 호출 `reduce` 를 돌렸다. 모듈 상수로 바꿨다. `UltraPachinko` 안에 따로 두던 `UL_WEIGHT_TOTAL_DEV` 중복도 지웠다 — 추첨과 표가 같은 값을 봐야 한다.

검증 (헤드리스 Chrome, 30만 판 몬테카를로)
- `drawPrize` 실측이 개발 가중치 이론값과 일치 (꽝 5.95% / 이론 5.97%)
- `drawPrizeCounts` 합계가 요청 판 수와 정확히 일치, 분포도 일치
- 사다리도 일치 (꽝 9.22% / 이론 9.21%)
- 표에 뜨는 값은 운영 기준 — 파칭코 꽝 52.86% · 사다리 꽝 80.23%
- **티켓당 기대 EXP 정합 확인**: 파칭코 997,495,663 vs 사다리 99,749,349,303 ÷ 100 = 997,493,493 → **1.000배**. `LADDER.cost: 100` 이 맞게 잡혀 있다 (개발 가중치로 계산되던 동안에는 이 정합을 확인할 수가 없었다)
- 미니게임 캔버스 60fps 유지 — 평균 16.7ms · 중앙값 16.7ms · 최악 16.8ms

훑어보고 문제 없다고 판단한 것 — 타이머는 전부 정리되고 있다(의식 연출의 10개도 배열로 모아 `forEach(clearTimeout)`), 페이지는 전부 lazy 이고 recharts 청크(111 kB gzip)는 기록·비교·인바디에서만 받는다, DOM 노드는 홈 378 · 파칭코 333 · 미니게임 126, 스토어는 NaN·2^53·localStorage 실패를 이미 다 막고 있다.


**전체 레벨 0 으로 초기화** (`dev/setLevel.js`)
- 1회 강제 적용 태그를 `lv0-1` → `lv0-2` 로 올렸다. 개발 빌드에서 다음 접속 때 브라우저마다 **딱 한 번** 걸린다 — 파칭코 EXP · UL EXP · 울트라 티켓 · 사용 티켓 · 기록 로그 · 최고 등급이 전부 지워지고 LV 0 이 된다 (초월·개벽 카드도 사라진다)
- 확인: 끝판 상태(누적 9,000조 · UL 8,000조 · 울트라 티켓 50)에서 접속 → 전부 비워지고 LV 0. 한 번 더 접속해도 다시 밀지 않는다(태그 소진)
- 운영 빌드에는 없는 경로다 (`if (!import.meta.env.DEV) return`). 또 밀고 싶으면 태그를 `lv0-3` 으로 올리면 된다


**사다리 확률표를 울트라 레전드 확률표와 같은 규격으로**
- **개발 확률을 진짜처럼 보여주고 있었다.** `if (DEV) miss.weight = 20000000` 으로 운영 가중치를 **덮어써서**, 메모리에 운영값이 남지 않았다. 그래서 개발 빌드의 확률표가 꽝을 `9.2%` 로 띄웠다 — 진짜는 `80.2%` 다. 원판표·울트라 확률표에서 이미 고쳤던 것과 같은 문제라, 같은 방식으로 `devWeight` 를 분리했다 (`ladderWeight` · `LADDER_WEIGHT_TOTAL_PROD` · `LADDER_HAS_DEV_WEIGHTS`)
- `LADDER_EXPECTED_EXP`(판당 평균)도 덮어쓴 가중치로 계산되고 있었다. 이제 운영 기준으로만 낸다
- 개발 빌드에서는 울트라와 똑같이 **⚠️ 경고 배너**가 뜨고, 지금 실제로 뽑히는 확률을 괄호로 적어준다 (`꽝 9.2%`)
- 확률을 계산 결과 그대로 찍어 `80.23271820847239%` 가 나오던 것을 `pctText` 로 잘랐다 — 1% 미만은 유효숫자를 살려서 `0.01%` 가 `0%` 로 뭉개지지 않는다
- 보상도 `999,999,999,999,999` 대신 `compactExp` 로 `+999조`
- 확인(개발 빌드): 꽝 80.2% · 소 15% · 중 4.5% · 대 0.201% · 초대박 0.01% · 판당 평균 ~997억 · 배너에 `꽝 9.2%`
- **남은 것**: 일반 파칭코(`PRIZES`)도 `if (DEV) miss.weight = 30000` 으로 똑같이 덮어쓴다. 확률표와 `EXPECTED_EXP` 가 같은 이유로 개발값을 보여준다


**개벽 100 → 250레벨, 등급 15개 추가**
- `하나`(90~99) 위로 15등급을 얹었다: 무 · 현 · 태허 · 불이 · 진여 · 법계 · 화엄 · 원융 · 무량 · 겁외 · 적광 · 상주 · 묘각 · 대원 · **무위**(240~250). "모든 것이 하나"에서 끝나던 자리라 그 위는 하나마저 지워지는 쪽으로 갔다
- 등급당 10레벨은 그대로. 총 25등급, 0~250 이 구멍 없이 이어진다
- **1레벨당 비용 80조 → 32조.** 늘린 게 아니라 줄여야 했다 — 80조 × 250 = 20,000조 로 2^53(9,007조)을 넘겨 정수 정밀도가 깨진다. 36조면 여유가 7조뿐이라 위험하고, **32조 × 250 = 8,000조** 면 누적 상한이 예전과 정확히 같아진다(여유 1,007조)
- 울트라 파칭코 보상은 `L = GENESIS.expPerLevel` 의 배수라 같이 줄어든다. 그래서 **판당 오르는 레벨 수는 그대로**고, 250레벨을 다 오르는 데 드는 판 수만 2.5배가 된다. 상품 문구("개벽 30레벨분")도 계속 맞는다
- 이미 UL EXP 를 모아둔 계정은 EXP 가 그대로인 채 **레벨 표시만 2.5배**가 된다 (개벽 40 → 100). 잃는 건 없다
- 최고 상품 `태초의 빛`(100 × L)은 이제 만렙이 아니므로 문구를 `개벽 100레벨분` 으로 고쳤다
- 헤드리스 Chrome 확인: 0→혼돈 · 40→윤회 · 99→하나 · 100→**무** · 200→적광 · 250→**무위/MAX LEVEL**, 상한 초과 입력은 250 으로 잘림, 등급표 25행(마지막 240~250)


**원판 피하기 — 피하기 보상 폐지, 점수는 주워야만 오른다**
- 원판이 바닥에 닿을 때마다 자동으로 붙던 `+1`(`DODGE.dodgeReward`)을 없앴다. 이제 **바닥 원판을 밟아 주운 값만** 점수가 된다 — 가만히 피하고만 있으면 판이 끝날 때까지 0
- 없앤 이유: 가만히 피하는 게 가장 안전한데 벌이도 같이 따라와서, "낙하 구간으로 다시 들어가 줍는다"는 이 게임의 유일한 판단이 있으나 마나였다. 한 판에 원판 120개가 떨어지니 피하기만으로 티켓 12장이 들어왔다
- `dodged` 는 그대로 센다 — 낙하 속도·생성 간격이 여기에 걸려 있고 결과창의 `피함 N` 표시에도 쓴다. 난이도 곡선은 전과 동일
- 원판표의 `피하면 🥏 +1` 행은 `피하기만 하면 🥏 0` 으로 바꿔 규칙을 못 보고 지나칠 수 없게 했다
- 착지 처리에 있던 `setScore` 도 뺐다 — 점수가 안 변하는데 원판이 떨어질 때마다 리렌더를 한 번씩 일으키고 있었다
- 수급은 줄어든다. 확률·교환비(🥏 10 → 🎫 1)·하루 판 수는 손대지 않았으니, 조일 게 아니라 풀 거라면 잭팟 `weight` 나 `GROUND.lifeMs`(바닥에 남는 4.2초)를 보는 게 맞다

**교환 수량 버튼 — 꾹 누르면 계속 오른다** (`useHoldRepeat`)
- 교환소에서 100장을 담으려면 `+10` 을 열 번 눌러야 했다. "최대"는 지갑을 통째로 담는 것뿐이라 그 사이 값은 연타밖에 방법이 없었다
- 두 화면이 같은 훅을 쓴다 — **교환소**(`+1`·`+5`·`+10`)와 **미니게임 티켓 교환**(`−`·`+`)
- 380ms 누르면 반복이 시작되고, 간격이 170ms → 40ms 로 짧아진다(×0.85). 짧게 탭하면 전과 똑같이 1만 움직인다 — `pointerdown` 에서 한 번 실행하고, 키보드(Enter·Space)는 `click.detail === 0` 으로만 받아 두 번 세지 않는다
- 상한에 닿으면 그 자리에서 멈춘다. 동작이 `false` 를 돌려주면 반복이 끝나는 구조
- **손 떼는 것은 `window` 에서 받는다.** 반복 중에 버튼이 `disabled` 되면 그 요소로는 `pointerup` 이 오지 않아서, 버튼에만 걸어두면 손을 떼도 계속 올라간다. 앱을 나갔을 때(`visibilitychange`)와 창이 포커스를 잃을 때도 멈춘다
- 헤드리스 Chrome 으로 확인: `+` 꾹 1.5초 → 1→7, 손 떼면 7에서 정지, 계속 누르면 최대 50에서 정확히 멈춤, 짧게 탭은 +1. 교환소도 `+10` 꾹 1.8초 → 80장(🎫 16,000)

**교환소 `최대` — 잠금 해제 + 꾹 누르면 교환 반복**
- 담아둔 수량이 꽉 차면(`pending >= affordable`) `최대` 도 같이 회색으로 죽었다. 이제 **바꿀 일반 티켓이 하나라도 있으면 언제나 눌린다** (`maxOk = unlocked && affordable >= 1`). 이미 꽉 찬 상태에서 눌러도 같은 값을 다시 넣을 뿐이라(React 가 같은 값이면 리렌더도 안 한다) 잠글 이유가 없었다
- **꾹 누르고 있으면 담기 + 확정이 반복된다.** 지갑이 빌 때까지 울트라 티켓이 계속 늘어난다
- **짧게 탭하면 지금까지처럼 담기만 한다.** 한 방향 교환이라 되돌릴 방법이 없어서 확정 단계를 둔 것인데, 스친 손가락 한 번에 지갑이 비면 그 안전장치가 무의미해진다. 되돌릴 수 없는 일을 하려면 0.4초를 계속 누르고 있어야 한다
- 이걸 위해 `useHoldRepeat` 이 동작에 `isRepeat` 을 넘기게 했다 — 첫 누름은 `false`, 꾹 눌러 반복되는 동안은 `true`. 탭과 홀드가 서로 다른 일을 할 수 있다
- 반복 중 교환은 `확정` 버튼과 같은 `busyRef` 연타 방어를 공유한다. 다만 아직 반영 전이면 그 tick 만 거르고 넘어간다 — 여기서 멈춰버리면 손은 누르고 있는데 아무 일도 안 일어난 채로 끝난다
- 꾹 누르기는 화면에 안 보이는 동작이라 버튼 줄 아래에 `최대를 꾹 누르고 있으면 바로 교환됩니다` 를 적었다
