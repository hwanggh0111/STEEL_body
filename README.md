# STEEL BODY

운동 기록 PWA. 운동·인바디를 기록하면 EXP와 티켓이 쌓이고, 그 티켓으로 파칭코·사다리·미니게임을 돌려 레벨을 올린다.

- **Frontend** `frontend/` — React 18 + Vite + Zustand + Recharts
- **Backend** `backend/` — Node.js + Express + SQLite, JWT 인증
- **배포** Render (`render.yaml`)

```bash
cd frontend && npm run dev     # http://localhost:5173
cd backend  && npm start       # http://localhost:4000
```

개발 편의 파라미터(개발 빌드 전용): `?level=N` `?level=max` `?tickets=N` `?reset=1`

## 레벨 체계

세 단계가 위로 쌓인다. 각 단계는 앞 단계를 다 채워야 열리고, 열리면 **0부터 다시 시작**한다.

| 단계 | 범위 | 화폐 | 여는 조건 |
|---|---|---|---|
| **일반** | LV 0 ~ 149 (30티어 × 5레벨) | EXP | 처음부터 |
| **초월** | 0 ~ 100 (10등급) | EXP · 1레벨당 80조 | LV 149 도달 |
| **개벽** | 0 ~ 100 (10등급) | ⚡ **울트라 레전드 EXP** · 1레벨당 80조 | 초월 100 |

누적 EXP 상한은 **8,999조**다. 일반 150레벨 + 초월 100레벨이 JS 안전 정수(2^53 = 9,007조)를 거의 다 쓰기 때문에, 개벽은 아예 다른 값(울트라 레전드 EXP)으로 센다. 한 숫자로 계속 세면 끝자리가 뭉개진다.

## 티켓 · 게임

```
운동/인바디 기록 ──┐
원판 피하기      ──┴─→ 🎫 일반 티켓 ──┬─→ 파칭코 (1장)      ─┐
                                      ├─→ 사다리 (100장)    ─┴─→ EXP
                                      └─→ 교환소 (200장)
                                              ↓
                                        🎟️ 울트라 티켓 ──→ 울트라 레전드 파칭코 (1장) ──→ ⚡ UL EXP
```

- 일반 티켓 보유 상한 150장 (넘으면 소멸, 안내 뜸)
- **티켓도 판 수도 "시작하는 순간" 확정 차감한다.** 연출이 끝날 때 차감하면 결과를 미리 보고 새로고침해서 무를 수 있다. 대신 연출 중 이탈하면 보상을 반드시 정산한다 (언마운트 + `pagehide` 양쪽)
- 원판 피하기의 **울트라 무한(∞)** 을 주우면 티켓이 영구히 안 닳는다 (지갑에 큰 수를 넣는 게 아니라 차감을 멈추는 방식)
- 확률표는 언제나 **운영 확률**을 보여준다. 개발 빌드에서 부풀린 값(`devWeight`)은 경고와 함께 따로 표시한다

# 개발 일지

최신이 위. 날짜 하나에 그날 한 일을 묶는다.

## 2026-08-18

**치명적 버그 2건**
- **`?reset=1` 이 운영 빌드에서도 돌았다.** 진행도는 전부 localStorage 에만 있고 되돌릴 수 없는데, 주소 하나로 확인 창도 없이 전멸했다. 링크를 눌리게만 해도 남의 기록을 날릴 수 있었다. `?level` · `?tickets` 과 같은 `import.meta.env.DEV` 가드를 붙였다 — 운영 번들에서 통째로 제거되는 것 확인
- **교환비(200장) > 티켓 보유 상한(150장).** 지갑을 꽉 채워도 울트라 티켓을 단 한 장도 못 바꿔서, 울트라 레전드 파칭코와 개벽 등급 전체가 운영에서 도달 불가능이었다. 상한은 무한 적립을 막는 값이지 소비처 크기를 정하는 값이 아니므로 **150 → 400**으로 올렸다 (`BASE_MAX_STACK`). 확률·교환비·기대값은 그대로라 개벽 난이도는 변하지 않는다
- 개발 도구가 상한을 하드코딩한 150 으로 되돌리던 것도 같은 상수를 쓰게 고침
- 교환소 **확정 연타** 방어 — 같은 프레임에 두 번 들어오면 반영 전 available 로 검사를 통과해 `used` 가 `earned` 를 넘었다. 받는 티켓은 제값이라 손익은 없지만 "아직 못 번 티켓을 미리 쓴" 상태가 된다. 성공했을 때만 잠그고 리렌더에서 푼다 (실패 때 잠그면 리렌더가 없어 영영 잠긴다)

**렌더 최적화 — 파칭코 페이지 DOM 노드 2,511 → 333**
- 릴의 숫자 띠를 칸마다 `<div>`로 쪼개 그리고 있었다. 파칭코 15칸 × 70 + 울트라 16칸 × 70 = **2,287개**, 페이지 전체 노드의 91%였다
- 칸마다 스타일이 전부 같으므로 줄바꿈으로 이어 붙인 텍스트 한 덩어리로 바꿨다. `white-space: pre` + 고정 `line-height`면 각 줄이 정확히 칸 높이라 보이는 건 같다 (실측 칸당 오차 0)
- `will-change: transform`을 도는 동안만 켜도록 했다. 켜둔 채로 두면 릴 31개가 영구히 레이어로 승격돼 모바일 GPU 메모리만 잡아먹는다
- 정적 확률표 합계(`PRIZES.reduce`)를 렌더마다 다시 더하던 것을 모듈 상수로
- **axios는 그대로 뒀다.** 토큰 갱신 큐·CSRF·재시도가 얽힌 인증 배관이라, 30 kB를 줄이자고 세션 버그를 만들 자리가 아니다
- 릴 착지 검증: 파칭코 4판·울트라 4판 모두 릴 숫자와 당첨 금액 일치

**울트라 레전드 파칭코 — 개벽 전용 기계와 울트라 티켓** `298d0cb`
- 새 레벨 단계(초월)에 들어가면 나오는 세 번째 기계. 보상이 ⚡ UL EXP라 개벽 등급이 바로 오른다
- 🎟️ **울트라 티켓** 신설 — 교환소에서 일반 티켓 200장을 1장으로 바꾼다. 판당 "200장"이 아니라 "1장"이라 남은 판 수가 바로 읽히고, 일반 파칭코·사다리와 지갑이 갈린다
- **교환소** — 수량을 담고 확정 버튼에서 한 번에 차감. 한 방향 교환이라 잘못 눌렀을 때 되돌릴 방법이 없어서다
- UL EXP의 출처를 이 기계 하나로 좁혔다. 상한 초과분을 넘기던 통로는 전용 기계가 없던 시절의 임시 통로였다
- 그 대신 상한 계정이 일반 파칭코를 돌리면 정말 아무것도 안 생기므로, 배너가 그럴 때만 `EXP 상한 — 티켓은 교환소에서`를 띄운다
- 판당 기대값 1.7조 — 개벽 1레벨당 🎟️ 47장. 끝판 콘텐츠라 일부러 멀게 잡았다

**개벽 등급 + 울트라 레전드 EXP (3차 레벨 체계)** `21c5362`
- 초월 100 위로 **개벽** 0~100 개방 (혼돈·태동·천지·만상·윤회·적멸·진리·도·창조·하나)
- 화폐를 나눈 건 취향이 아니라 필요다 — 누적 EXP가 이미 2^53을 거의 다 쓴다
- 정밀도 버그: `award`가 자르기 **전에** 더하는 구조라 그 합이 2^53을 넘어 끝자리가 뭉개졌다. 남은 자리를 먼저 구해 나누도록 고침
- 획득 배너가 개벽 > 초월 > 일반 순으로 "아직 움직이는 레벨"을 고르게 함 (안 그러면 만렙 이후 영원히 `LV 149 → LV 149`)

**사다리에 더블 오어 나씽** `f441be5`
- 사다리는 시작점을 골라도 결과가 같았다 — 보상을 먼저 뽑고 도착 칸에 놓는 구조라 선택이 연출이었다
- 당첨 판을 바로 적립하지 않고 손에 들려주고, 챙길지 한 번 더 걸지 고르게 함. 배수판 `×2 ×2 본전 꽝 꽝` — 기대값 정확히 1.0이라 모드 전체 밸런스는 그대로, 분산만 커진다
- 배수 칸은 미리 보이고 가로줄만 출발할 때 생긴다. 여기서는 결과를 진짜 사다리가 정한다
- 배치는 피셔-예이츠로 섞는다. 사다리 도착 분포가 칸마다 다르고(1번 출발 시 30/27/19/14/10%) `sort(random-0.5)`도 균등하지 않아 둘이 겹치면 기대값 1.0이 깨진다
- `LadderGame`에 `pagehide` 정산이 없던 것도 같이 메움

**`?tickets=N` 개발용 티켓 조절** `7b03d65` · **이벤트 페이지 제거** `a554d2e`
- 출시 기념 이벤트 페이지와 진입 경로 전부 제거. 캐치올 라우트(`path="*"`)를 넣어 옛 북마크·PWA 캐시를 홈으로 보낸다

## 이 문서를 쓰는 규칙

- **개발할 때마다 여기 정리한다.** 커밋을 남겼으면 그날 항목에 한 줄 이상 추가한다
- 날짜 섹션은 **최신이 위**. 같은 날 작업은 한 섹션 안에 묶는다
- 각 항목에 **커밋 해시**를 붙인다 — 자세한 내용은 커밋 메시지에 있다
- 무엇을 했는지보다 **왜 그렇게 했는지**를 남긴다. 코드에서 안 보이는 건 그것뿐이다
- 되돌린 결정, 빠진 함정도 적는다. 다음에 같은 자리에서 또 넘어지지 않으려고 쓰는 문서다
