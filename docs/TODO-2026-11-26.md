## 높음 — 사람이 적은 것이 조용히 사라진다

### 1. ★ 오프라인 줄을 고치거나 지웠는데 서버에 안 간다
- `frontend/src/store/workoutStore.js:289-306` (`updateWorkout` · `deleteWorkout`)
- `local-` 로 시작하는 id 면 **줄(queue)에서만** 고친다. 그런데 그 줄이 그 사이 올라가
  줄에서 빠졌으면 `editInQueue`(`data/offline.js:147`)가 **아무것도 못 찾고** 그대로
  `{ queued: true }` 를 돌려준다 — 서버는 옛 값 그대로, 오류도 없다. 지우기도 같다.
- 재현: 지하에서 적은 줄(대기 중)을 수정 칸에 연다 → 위층에서 신호가 돌아와 올라간다 →
  80 을 85 로 고쳐 저장 → 서버는 80. (올라가는 중에 고친 경우도 옛 값이 실린다)
- 실마리: 서버 줄에 `client_key` 가 그 로컬 id 로 남는다(`backend/src/db.js` createWorkout).
  줄에 없으면 `client_key === id` 인 서버 줄을 찾아 그 id 로 PUT/DELETE 하면 된다.

### 2. ★ 같은 파일 안의 똑같은 줄을 「이미 있다」로 버린다 (가져오기)
- `backend/src/routes/importData.js:134-151` — `have` 가 **Set** 이라 첫 줄을 넣고
  `have.add(k)` 하면, 같은 파일의 똑같은 둘째 줄이 `skipped` 가 된다.
- 재현: 11/01 벤치 60kg 1×10 을 세 줄로 적은 사람 → 내보내고 → 빈 계정에 넣기 →
  `added 1 · skipped 2`. **복원하려고 만든 길에서 두 세트가 사라진다.**
- 11/24 `f463d37` 의 「두 번 넣어도 안 늘어난다」 확인은 **서로 다른 줄**만 봤다 —
  근호도 11/25 감사에서 이 자리를 놓쳤다.
- 고칠 길: 열쇠를 **개수로** 센다(이미 있는 수 vs 파일 안의 수 — 다중집합).
  `room = spec.max - have.size` 도 같이 줄 수로(지금은 열쇠 수라 상한이 덜 센다).

### 3. ★ 목표를 못 불러왔을 때 빈 칸으로 저장하면 진짜 목표를 덮는다
- `frontend/src/pages/GoalPage.jsx:304` — `showForm = editing || ((loaded || failed) && !hasGoal(goal))`.
  불러오기가 **실패**해도 `goal` 이 null 이라 「목표 세우기」 빈 칸이 뜬다.
- 저장하면 `:270` 이 `startedAt = today` 를 싣고, 비운 칸은 null 로 간다 →
  서버 `routes/goals.js` 의 `clean()` 이 null 을 「지운다」로 읽어 합친다 →
  **다른 목표가 지워지고 시작일이 오늘로**, 지난 막대가 「목표 세우기 전」이 된다.
- 고칠 길: `failed` 면 칸을 그리지 않고 「다시 불러오기」만 둔다.

## 중간

### 4. 오프라인으로 올린 줄의 시각이 「올린 시각」이다
- `frontend/src/store/workoutStore.js:381` 이 `q.at`(적은 순간)을 안 보내고,
  서버(`backend/src/db.js:984`)는 받은 순간을 `created_at` 으로 찍는다.
- 지하에서 적은 한 판이 몇 초 간격으로 찍혀 `pace.js` 가 「몰아 적은 날」로 보고
  운동 시간 줄이 사라지고, 그날 줄 순서도 온라인 줄과 섞인다.
- 시안 1125 ①(알림 시각 vs 실제 시각)이 막힌 까닭도 이것이다 — 같은 칸이 둘을 푼다.

### 5. 루틴 진행 칸(오프라인에서 누른 것)이 앱을 다시 켜면 안 올라간다
- `frontend/src/components/Layout.jsx:308` · `store/routineSessionStore.js:84`
- 담아둔 칸은 `fetch()` 가 읽는데, 켤 때의 올리기(flush)가 그보다 **먼저** 돌아 빈 줄을 본다.
  다음 `online` 사건 때만 다시 올린다. 로그아웃하면 「못 올린 것」 경고 없이 사라진다.

### 6. 메모 올리기에 세션 확인이 없다 (다른 사람 계정으로 올라갈 수 있다)
- `frontend/src/store/noteStore.js:181-187` — 운동 · 루틴 올리기와 달리 `isSameSession`
  을 안 본다. A 가 느린 LTE 에서 올리다 나가고 B 가 들어오면 남은 A 메모가 **B 쿠키로**
  올라가고, 같은 날짜의 B 메모 줄을 `dropEntry` 가 지울 수 있다.
- 같은 꼴 작은 것: `workoutStore.js:381-393` 은 보내기 **전**에만 보고, 답이 온 **뒤**엔
  안 봐서 A 줄이 B 목록에 잠깐 꽂힌다(다음 전체 받기까지).

### 7. 내보낸 파일을 다시 넣으면 그날 줄 순서가 뒤집혀 드롭 · 슈퍼 묶음이 어긋난다
- `backend/src/routes/export.js:34` 는 최신이 앞(`db.js:767` ROW_CMP)으로 쓰고,
  가져오기는 파일 순서대로 넣어 `created_at` 이 거꾸로 붙는다.
  화면은 「앞 줄」을 `created_at` 오름차순으로 정한다(TrainPage `linkBoundary` · `dayRoutine.js`).
- 재현: 60kg → 40kg(드롭) → 내보내고 다시 넣기 → 드롭이 먼저 와서 엉뚱한 줄에 붙는다.
- 고칠 길: 가져올 때 날짜 안에서 거꾸로 넣거나, 파일에 순서(시각)를 싣는다.

### 8. 치수 기록을 다시 넣을 때마다 두 벌이 된다
- `backend/src/routes/export.js:90` 이 `data` 안의 `date` 를 빼고 쓰는데,
  `measureKey`(`csvRows.js:506`)는 `data` 의 열쇠를 전부 본다 —
  저장된 줄에는 `date` 가 들어 있다(BodySizeSection 이 `{ ...values, date }` 로 보낸다).
- 같은 측정 CSV 를 두 번 넣으면 `skipped 0` 으로 치수가 또 들어간다.
