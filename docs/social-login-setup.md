# 소셜 로그인 켜기 — 네이버 · 인스타그램 · 트위터(X)

> **코드는 다 돼 있습니다. 남은 것은 열쇠뿐입니다.** (2026-10-07)
>
> 구글은 10/1 에 이미 켰습니다 — 그쪽 절차는 [google-login-setup.md](google-login-setup.md) 에 있습니다.
>
> 이 문서는 **근호님이 직접 하셔야 하는 일**만 모았습니다. 열쇠는 계정 주인만 받을 수 있습니다.

---

## 0. 먼저 알아둘 것 — 세 가지

### ① 돌아올 주소는 **화면이 아니라 서버**입니다

제일 많이 틀리는 자리입니다. 콘솔에 넣는 주소는 **4000**(서버)이고, 5173(화면)이 아닙니다.

| 언제 | 넣을 주소 |
|---|---|
| 내 컴퓨터 | `http://localhost:4000/api/oauth/<제공자>/callback` |
| 배포한 뒤 | `https://<배포주소>/api/oauth/<제공자>/callback` |

`<제공자>` 자리에 `naver` · `instagram` · `twitter` 를 넣습니다. **한 글자도 다르면 막힙니다** — 끝의 `/` 하나까지 봅니다.

### ② 인스타와 X 는 **메일 주소를 주지 않습니다**

이 앱은 이메일 하나로 계정을 잇습니다. 그래서 그 둘로 들어온 사람에게는 앱이 **메일을 한 번 묻습니다** (`/oauth/email` 화면). 번호를 메일로 보내 확인하고, 그때 계정을 만듭니다.

그 말은 — **SMTP 가 켜져 있어야 인스타와 X 가 끝까지 돕니다.** 10/1 에 지메일 앱 비밀번호로 켜뒀으니 내 컴퓨터에서는 됩니다. **배포할 때 Render 에도 같은 값을 넣어야 합니다.**

### ③ 넣은 것만 단추로 나옵니다

열쇠가 없는 제공자는 로그인 화면에 **단추가 아예 안 그려집니다**. 하나씩 받아서 하나씩 켜도 됩니다 — 순서는 상관없습니다.

서버가 뜰 때 무엇이 꺼져 있는지 스스로 말합니다.

```
[oauth] 열쇠가 없어 꺼진 소셜 로그인: 네이버 · 인스타그램 · 트위터(X) (나머지는 켜집니다)
```

## 1. 네이버 — 제일 쉽습니다

**메일을 주기 때문에** 받아서 넣으면 바로 끝납니다. 묻는 걸음도 없습니다.

### 받는 절차

1. <https://developers.naver.com/apps/#/register> 로 갑니다 (네이버 계정으로 로그인)
2. **애플리케이션 이름** — `STEEL BODY` (로그인 동의 화면에 이 이름이 뜹니다)
3. **사용 API** — `네이버 로그인` 을 고릅니다
4. **제공 정보 선택** — 여기가 중요합니다

   | 항목 | 어떻게 |
   |---|---|
   | **이메일 주소** | **필수**로 둡니다 ← ⚠ 이것만 꼭 |
   | 별명 | 필수 (앱에서 이름으로 씁니다) |
   | 나머지 | 안 씁니다 — 고르지 않습니다 |

   «이메일 주소»를 선택으로 두면, 동의를 안 켠 사람이 「메일 주소를 알려주세요」 걸음으로 떨어집니다. 되기는 되지만 걸음이 하나 더 늘 뿐입니다.

5. **환경 추가** → `PC 웹` 을 고릅니다
6. **서비스 URL** — `http://localhost:5173` (배포 뒤에는 배포 주소)
7. **Callback URL** — **여기가 서버입니다**

   ```
   http://localhost:4000/api/oauth/naver/callback
   ```

8. 등록하면 **Client ID** 와 **Client Secret** 이 나옵니다

### 넣을 곳

`backend/.env` 에 두 줄 (이 파일은 git 에 안 올라갑니다)

```
NAVER_CLIENT_ID=받은_아이디
NAVER_CLIENT_SECRET=받은_열쇠
```

### 됐는지 어떻게 아나

- 서버를 다시 띄우면 꺼진 목록에서 **「네이버」가 사라집니다**
- `http://localhost:4000/api/oauth/providers` 가 `"naver": true`
- 로그인 화면에 **초록 「네이버」 단추**가 나타납니다
- 눌러서 들어오면 끝입니다

## 2. 인스타그램 — 받기 전에 알아야 할 것이 있습니다

### ⚠ 개인 계정은 들어올 수 없습니다

인스타의 옛 로그인(Basic Display)이 2024년 말에 닫혔습니다. 지금 남은 것은 `instagram_business_basic` 하나이고, 이것은 **비즈니스 · 크리에이터 계정만** 통과시킵니다.

개인 계정으로 단추를 누르면 **인스타 쪽에서 막습니다** — 우리 쪽에서 해줄 수 있는 것이 없습니다. 단추를 켤지 말지 판단하실 때 이 점을 보고 정하시면 됩니다.

> 참고 — 본인 인스타를 **프로페셔널 계정**으로 바꾸면 들어옵니다 (설정 → 계정 종류 → 전환). 무료고 되돌릴 수 있습니다. 쓰는 사람에게 그걸 시킬 수는 없으니, 이 단추는 **「되는 사람만 쓰는 길」**로 두는 셈입니다.

### 받는 절차

1. <https://developers.facebook.com/apps/> → **앱 만들기** (페이스북 계정으로 로그인)
2. **사용 사례** — `다른 사용 사례 살펴보기` → `Instagram` → **Instagram API 설정**
3. 왼쪽 메뉴에서 **Instagram** → **API 설정**
4. **Instagram 비즈니스 로그인 설정** 칸에서

   | 항목 | 넣을 값 |
   |---|---|
   | **리디렉션 URL** | `http://localhost:4000/api/oauth/instagram/callback` |
   | **삭제 콜백 URL** | 비워둬도 됩니다 (개발 중) |

5. 같은 화면의 **Instagram 앱 ID** 와 **Instagram 앱 시크릿** 을 받습니다
6. **테스트 사용자 추가** — 앱이 심사를 안 받은 상태에서는 여기 넣은 계정만 들어옵니다. 본인 인스타 계정을 넣고 **인스타 쪽에서 초대를 수락**해야 합니다

### 넣을 곳

```
INSTAGRAM_APP_ID=받은_앱_아이디
INSTAGRAM_APP_SECRET=받은_시크릿
```

> ⚠ 이름이 `CLIENT_ID` 가 아니라 **`APP_ID`** 입니다. 페북 쪽 이름을 그대로 따랐습니다.

### 됐는지 어떻게 아나

- `providers` 가 `"instagram": true`
- 로그인 화면에 **인스타 색 그라디언트 단추**가 나타납니다
- 누르면 인스타로 갔다가 돌아와서 **「거의 다 됐어요」 화면**이 뜹니다 — 메일 주소를 묻는 자리입니다
- 메일을 적고 번호를 넣으면 계정이 만들어집니다

## 3. 트위터 (X)

### 받는 절차

1. <https://developer.x.com/en/portal/dashboard> 로 갑니다 (X 계정으로 로그인)
2. 개발자 계정이 없으면 만듭니다 — **Free** 등급으로 충분합니다 (로그인만 쓰므로)
3. **Projects & Apps** → 앱을 하나 만듭니다 (`STEEL BODY`)
4. 그 앱의 **User authentication settings** → **Set up**
5. 설정은 이렇게 둡니다

   | 항목 | 고를 것 | 까닭 |
   |---|---|---|
   | **App permissions** | `Read` | 글을 쓰지 않습니다 |
   | **Type of App** | **`Web App, Automated App or Bot`** | ← 이걸 고르면 Confidential client 가 됩니다 |
   | **Callback URI** | `http://localhost:4000/api/oauth/twitter/callback` | **서버**입니다 |
   | **Website URL** | `http://localhost:5173` (배포 뒤에는 배포 주소) | |

6. 저장하면 **Client ID** 와 **Client Secret** 이 한 번 뜹니다 — **그 자리에서 복사하세요.** 다시 안 보여줍니다 (다시 발급은 됩니다)

### 넣을 곳

```
TWITTER_CLIENT_ID=받은_아이디
TWITTER_CLIENT_SECRET=받은_열쇠
```

> **`Public client` 로 만들었으면 SECRET 줄을 비워둡니다.** 섞으면 X 가 `invalid_client` 로 거절합니다 — 앱은 SECRET 이 있을 때만 그것을 보냅니다.

### 됐는지 어떻게 아나

- `providers` 가 `"twitter": true`
- 로그인 화면에 **검정 `𝕏` 단추**가 나타납니다
- 누르면 X 로 갔다가 돌아와서 **「거의 다 됐어요」 화면**이 뜹니다 (X 도 메일을 안 줍니다)

### 메일을 받으려면

X 는 **「다름 승인」(Elevated / 추가 권한 요청)** 을 받으면 메일 주소를 줍니다. 심사를 거쳐야 하므로 지금은 묻는 걸음으로 갑니다.

**승인이 나면 고칠 데가 없습니다** — 메일이 실려 오면 앱이 그대로 통과시키고 묻지 않습니다. 코드에 그렇게 넣어뒀습니다.

## 4. 배포할 때 — Render 에 같은 값을 넣습니다

`backend/.env` 는 **내 컴퓨터 것**입니다. 배포본은 Render 대시보드의 값을 봅니다.

1. Render → 해당 서비스 → **Environment**
2. `render.yaml` 에 자리는 이미 만들어져 있습니다 (`sync: false` = 손으로 넣는 값). 거기에 값만 채웁니다

   ```
   NAVER_CLIENT_ID          NAVER_CLIENT_SECRET
   INSTAGRAM_APP_ID         INSTAGRAM_APP_SECRET
   TWITTER_CLIENT_ID        TWITTER_CLIENT_SECRET
   SMTP_HOST  SMTP_USER  SMTP_PASS      ← 인스타·X 가 이걸 씁니다
   ```

3. **각 콘솔에 배포 주소의 콜백도 등록합니다.** 내 컴퓨터 주소만 넣어두면 배포본에서 전부 막힙니다

   ```
   https://<배포주소>/api/oauth/naver/callback
   https://<배포주소>/api/oauth/instagram/callback
   https://<배포주소>/api/oauth/twitter/callback
   ```

> ⚠ **배포 주소가 아직 둘입니다.** 구글 콘솔에는 `steel-body.onrender.com`, `render.yaml` 에는 `blackiron.onrender.com` 이 적혀 있습니다. **배포 전에 하나로 맞춰야** 구글 로그인이 안 막힙니다 — 새로 등록하는 셋도 맞춘 주소로 넣으시면 됩니다.

## 5. 막혔을 때 — 오류 글자로 찾기

화면에 뜨는 말과 주소줄의 `?error=` 를 같이 보면 어디가 막혔는지 바로 나옵니다.

| 주소줄에 이게 보이면 | 뜻 | 할 일 |
|---|---|---|
| `*_not_configured` | 열쇠가 없다 | `.env` 에 넣고 **서버를 다시 띄웁니다** (고쳐도 다시 안 띄우면 안 읽습니다) |
| `invalid_state` | 그 브라우저에서 시작한 것이 아니다 | 링크를 복사해 다른 브라우저에서 열었거나, 10분이 지났거나, 쿠키를 막아둔 것입니다. **처음부터 다시** 누릅니다 |
| `*_no_email` | 제공자가 메일을 안 줬다 | 네이버면 «이메일 주소»를 **필수**로 바꿉니다. 인스타·X 는 원래 안 주므로 이 글자가 보이면 안 됩니다 — 보이면 알려주세요 |
| `*_unverified` | 제공자가 「확인 안 된 주소」라고 했다 | 그쪽 계정에서 메일 확인을 끝냅니다 |
| `*_failed` | 그 밖의 일 | 서버 로그를 봅니다. 내 컴퓨터에서는 `OAuth error: ...` 가 찍힙니다 |
| `redirect_uri_mismatch` <br> (제공자 화면에서) | 콜백 주소가 안 맞다 | **5173 이 아니라 4000** 인지, 끝의 `/` 가 같은지 봅니다 |
| `invalid_client` <br> (X 에서) | 열쇠 방식이 안 맞다 | Public client 인데 SECRET 을 넣었거나 그 반대입니다. **한쪽으로** 맞춥니다 |

### 메일 묻는 걸음에서 막혔을 때

| 화면이 이렇게 말하면 | 뜻 |
|---|---|
| 「지금은 메일을 보낼 수 없어요」 | SMTP 가 꺼져 있습니다. `.env` 의 `SMTP_*` 를 봅니다 |
| 「시간이 지났어요. 다시 로그인해주세요」 | 15분이 지났습니다. 다시 누르면 됩니다 |
| 「인증번호가 틀렸어요」 | 번호 다섯 번까지 틀릴 수 있고, 그 뒤에는 다시 받아야 합니다 |

## 6. 코드 쪽에서 봐둘 것

| 보는 법 | 무엇을 보나 |
|---|---|
| `cd backend && npm run oauth` | 네 길을 **제공자 없이** 한 바퀴 돌립니다. 열쇠가 없어도 돕니다 — 메일 묻는 걸음, PKCE, 쪽지 한 번 쓰기, 이미 쓰는 메일에 잇기까지 봅니다 |
| `cd backend && npm run check` | 그 안에 위 검사도 들어 있습니다 |
| `GET /api/oauth/providers` | 지금 어느 길이 켜져 있나 (열쇠 값은 안 돌려줍니다) |
| 서버 기동 줄 | 무엇이 꺼져 있나 |

### 걷어낸 것

- **카카오** — 10/7 에 넣었다가 그날 뺐습니다. 코드와 검사가 다 됐었고, 뺀 까닭은 기술이 아니라 **쓰기 불안하다는 판단**입니다. 메일을 주고 `is_email_verified` 까지 주므로 **이 앱에 제일 잘 맞던 제공자**였습니다
- **페이스북** — 같은 날 걷어냈습니다. 쓰지 않는 길을 두면 고칠 때 잊힙니다

둘 다 **그날 커밋을 되돌리면 살아납니다.**
