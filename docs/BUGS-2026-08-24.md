# 버그 보고서 — 앱 전체 훑기 · 보안 점검

작성일: 2026-08-24
대상: 앱 전체 (`frontend/src`, `backend/src`) — 고객센터를 앱에 붙이면서 그동안 안 보던 화면까지 같이 훑었다
검증 방법: 코드 정독 + 로직만 떼어내 node 로 재현 + 실제 API 호출. **브라우저로 확인한 것은 아니다**
관련: [BUGS.md](BUGS.md) (파칭코 · 사다리 · 미니게임, 2026-08-17), 루트 README 의 개발 일지 2026-08-24

`위험` 은 되돌릴 수 없거나 남에게 열려 있는 것, `높음` 은 정상적으로 쓰는 사람이 겪는 것이다.

## 보안

### S-1 · 아무나 배포한 사이트가 이 API 를 부를 수 있었다 — 위험

**증상** — 없음. 겉으로는 아무 문제가 없다.

**원인** — `index.js` 의 CORS 허용 판정.

```js
if (origin.endsWith('.onrender.com')) return callback(null, true);
```

`credentials: true` 와 함께 있었다. Render 는 누구나 무료로 배포할 수 있는 곳이다 — `evil-xxx.onrender.com` 을 띄우고 그 페이지에서 `credentials` 를 실어 이 API 를 부르면, **로그인해 있는 사람이 그 페이지를 열기만 해도** 그 사람 자격으로 요청이 나가고 응답까지 읽힌다.
`routes/oauth.js` 의 `isAllowedFrontendOrigin` 과 호스트 검증에도 같은 와일드카드가 있었다 — 열린 리다이렉트다.

**고침** — 와일드카드 삭제. `FRONTEND_URL` 에 이미 정확한 주소(`https://steel-body.onrender.com`)가 들어 있어 애초에 필요 없었다. Render 가 넣어주는 `RENDER_EXTERNAL_URL` 도 같이 받아 배포 이름이 바뀌어도 끊기지 않게 했다.

**확인** — 허용된 origin 200 / `https://evil-test.onrender.com` 403, `Access-Control-Allow-Origin` 헤더가 아예 안 붙는다.

### S-2 · Bearer 헤더 하나로 CSRF 검사를 건너뛸 수 있었다 — 위험

**원인** —

```js
if (req.headers.authorization?.startsWith('Bearer ')) return next();
```

Bearer 만 쓰는 요청에 CSRF 가 필요 없다는 건 맞다. 그런데 **헤더가 있으면 통과** 로 둔 게 문제다. `auth` 미들웨어는 쿠키를 먼저 읽는다 — 아무 값이나 담은 Bearer 헤더를 붙이면 CSRF 검사만 건너뛰고 인증은 쿠키로 통과한다. S-1 과 겹치면 그대로 뚫린다.

**고침** — 인증 쿠키가 없을 때만 건너뛴다.

### S-3 · 자동 판정이 계정과 모든 데이터를 지웠다 — 위험

**원인** — `middleware/aiGuard.js` 의 `executeLevel4` 가 `db.deleteUserCompletely(userId)` 를 직접 불렀다. 판정이 틀리면 몇 년치 운동 기록이 **되돌릴 방법 없이** 사라진다. 이르는 길도 짧았다 — `executeLevel3` 은 정지가 2회 누적되면 스스로 LEVEL 4 로 올린다.

2026-08-21 에 욕설 경로에서 이 함수를 일부러 떼어냈는데(`utils/abusePolicy.js` 주석 참고), 같은 지뢰가 aiGuard 본체에 그대로 있었다.

**고침** — 막는 것(영구 정지 · 로그인 차단 · 이메일/IP 블랙리스트)은 자동으로, **없애는 것은 사람이.** IP 대역(`/24`) 자동 차단도 뺐다 — 통신사 NAT 뒤에 있는 사람들이 통째로 걸린다.
자동 삭제를 없앤 대신 사람이 지울 길을 열었다 — `DELETE /api/security/user/:id`.

- 관리자는 못 지운다
- **이미 막혀 있는 계정만** 지울 수 있다 (영구 정지 · `is_banned` · 차단)
- **지울 계정의 이메일을 본문에 그대로 적어야 한다**

**확인** — 멀쩡한 사용자 400 / 관리자 400 / 없는 사용자 404. 세 경우 모두 아무것도 지워지지 않았다.

### S-4 · 정상적으로 운동을 적으면 7일 정지됐다 — 높음

**원인** — 스팸 기준이 **10건/분**. 그런데 운동은 기록 하나가 POST 하나다. 운동을 끝내고 앉아서 몰아 적으면 5개 종목 × 3세트만 해도 15건이다. 걸리면 `executeLevel3` 으로 7일 정지, 두 번 걸리면 S-3 으로 이어졌다.

**고침** — 기준을 60건/분으로 올리고, **정지 대신 429 로 되돌려 보낸다.** 너무 빠른 것과 나쁜 뜻으로 하는 것은 다르고, 이 판정만으로 사람을 일주일 막아 세우기에는 근거가 약하다. 진짜 공격은 IP 차단과 rate limit 이 잡는다.

### S-5 · 관리자가 자동 처벌에 걸렸다 — 위험

**원인** — `middleware/auth.js` 는 관리자를 정지 검사에서 빼준다. 그런데 **처벌을 거는 쪽**(`executeLevel3` · `executeLevel4`)은 관리자를 보지 않았다. 관리자가 잠기면 자기 정지를 자기가 못 풀어 서비스가 통째로 멎는다.

**고침** — 두 함수 모두 관리자면 기록만 남기고 건너뛴다.

### S-6 · `unblock` 이 관리자 권한을 지웠다 — 높음

**원인** — `POST /api/security/unblock-user/:id` 가 대상이 누구든 역할을 `'user'` 로 덮어썼다. `revoke-admin` 에는 자기 자신을 지키는 장치가 있는데 이쪽으로는 그냥 통과했다.

**고침** — `role === 'blocked'` 인 사람만 푼다. 더해서 **마지막 관리자는 강등할 수 없게** 했다 — 자기 자신만 막아두면 관리자 둘이 서로를 내리는 길이 남는다.

### S-7 · 대문자로 가입하면 계정이 둘로 갈렸다 — 높음

**증상** — `Kevin@Gmail.com` 으로 가입한 사람이 `kevin@gmail.com` 으로 로그인하면 「없는 계정」. 게다가 그 주소로 **또 가입이 된다.** 같은 사람의 계정이 둘로 갈리고 기록도 갈린다 — 본인에게는 **「기록이 사라졌다」** 로 보인다.

**고침** — 저장은 적은 그대로 두고, 찾고 비교할 때만 낮춘다(`db.emailKey`). 인덱스 · 중복 검사 · `ADMIN_EMAIL` 판정 전부.

**확인** — `DEV3@Local.DEV` 로 로그인하면 `dev3@local.dev` 와 같은 계정(userId 7).

### S-8 · 사진 자리에 사진이 아닌 것을 넣을 수 있었다 — 보통

`POST /api/photos` 가 아무 문자열이나 2MB 까지 받아 그대로 돌려줬다. `data:image/(png|jpe?g|gif|webp|avif);base64,` 로 시작하는 것만 받는다.

## 앱 화면

### A-1 · 홈트 타이머가 첫 운동만 하고 나머지를 전부 건너뛰었다 — 높음

**증상** — 8개짜리 프로그램을 시작하면 운동 1번을 하고, 그 다음부터는 **운동 단계가 통째로 사라진 채 휴식만 이어지다** 끝난다.

**원인** — effect 두 개가 각자 `timeLeft` 를 건드렸다. 휴식이 끝나 다음 운동으로 넘어가는 commit 에서 둘이 같이 돌면서 한쪽은 「휴식 시작」, 다른 쪽은 「운동 시간」 을 써 넣는다. 마지막에 쓴 값이 남아 **`isRest` 는 true 인데 시간은 운동 시간** 인 상태가 된다.

**재현** — 두 effect 의 deps 규칙을 그대로 옮겨 node 로 돌렸다.

```
운동 1 (A) 3초 → 휴식 2초 → (B 건너뜀) 휴식 3초 → (C 건너뜀) 완료
```

**고침** — 단계 전환을 `beginPhase` 한 곳으로 모았다. 지금 단계는 ref 에 들고, effect 는 시계만 본다.
같이 고친 것 — **남은 초를 1씩 빼던 것**은 화면을 내리거나 다른 탭을 보는 동안 브라우저가 타이머를 늦춰서 30초 플랭크가 1분이 됐다. 끝나는 시각을 정해두고 250ms 마다 시계를 다시 본다.

**확인** — `A 3초 → 휴식 2초 → B 3초 → 휴식 2초 → C 3초`, 정확히 13초에 완료.

### A-2 · 네이버 · 페이스북 · 인스타그램 로그인이 100% 실패했다 — 높음

**원인** — `generateState()` 는 state 문자열을 만들기만 하고, Map 에 등록하는 줄은 부르는 쪽에 있었다. **구글만 그 줄을 갖고 있었다.** 나머지 셋은 콜백의 `validateState` 가 언제나 `has(state) === false` 로 떨어져 `invalid_state` 로 튕겼다.

**고침** — 발급 안에서 등록까지 한다. 빠뜨릴 수 있는 자리를 없앤다.

**확인** — 네 곳 모두 통과, 같은 state 를 두 번 쓰면 여전히 막힌다(1회용).

### A-3 · 보안 대시보드가 안전한 서버를 위험하다고 보고했다 — 보통

**원인** — 화면은 `jwt.expiry` · `helmet.enabled` · `cors.origins` · `rateLimit.login.max` 를 읽는데, 서버는 `jwtAccessExpiresIn` · `helmetEnabled` · `corsOrigin` 처럼 평평한 이름으로 보냈다. 그래서 JWT 만료는 빈칸, **Helmet 은 `비활성화 · 위험`**(실제로는 켜져 있다), CORS 는 없음, Rate Limit 은 위험으로 떴다.
숫자도 손으로 적어둔 값이라 실제와 달랐다 — `분당 100회` 를 `15분당 100회` 로, 로그인 제한(15분당 20회)은 아예 없는 값으로 보고했다.
판정 함수도 틀렸다 — `parseInt('15m')` 를 시간으로 읽어 **15분짜리 만료를 15시간으로** 보고 `주의` 를 띄웠고, rate limit 은 창 길이를 안 보고 횟수만 봤다.

**고침** — `backend/src/config/security.js` 에 rate limit · JWT · bcrypt · body 한도를 모았다. `index.js` 가 적용하고 대시보드가 같은 것을 읽는다. 판정은 단위를 보게 고쳤다.

### A-4 · 이미 만든 루틴에 두 번째 운동을 넣을 수 없었다 — 높음

**원인** — 추천 화면의 `내 루틴에 추가` 는 같은 이름의 루틴이 있으면 「이미 포함된 운동이에요」 라며 돌려보냈다. **그 운동이 실제로 들어 있는지는 보지도 않았다.** 게다가 고칠 길도 없었다 — 루틴을 **고치는** API 자체가 없었다.

**고침** — `PUT /api/my-routines/:id` 를 만들고(남의 루틴은 못 고친다), 이미 있는 루틴이면 이어붙인다.

## 앱 바깥 (점검 · 오프라인 · 공용 부품)

### M-1 · 점검을 잡아도 아무에게도 안 떴다 — 높음

**증상** — 관리자 화면에서 점검을 잡아도 다른 사람에게는 점검 화면이 안 뜬다. 고객센터의 `점검 예정` 도 영영 비어 있다.

**원인** — 점검 스케줄이 **관리자 브라우저의 localStorage 에만** 있었다. 백엔드에 관련 코드가 한 줄도 없다. 관리자가 브라우저를 바꾸면 자기 설정도 사라졌다. **기능이 있는 것처럼 보였을 뿐이다.**

**고침** — `GET /api/maintenance`(누구나) · `PUT /api/maintenance`(관리자). 화면은 캐시로 먼저 그리고 서버에서 받아 갱신한다 — 목록을 못 받은 것 때문에 앱이 안 열리면 안 된다. 목록은 5분마다, 시각 계산은 그대로 1초마다.
서버가 모양을 검사한다. 모르는 키는 버리고 **하루를 넘는 점검은 안 받는다** — 넘기면 화면이 영원히 잠긴다.

**확인** — 일반 계정 403 / 관리자 200(모르는 키 버려짐) / `durationMin: 99999` 는 기본값으로 / 목록이 아니면 400.

### M-2 · 인터넷이 끊기면 앱이 아예 안 열렸다 — 높음

**원인** — 서비스 워커가 네트워크 실패 시 `caches.match(요청)` 을 그대로 돌려줬다. 이 앱은 한 페이지짜리라 `/support` · `/history` 같은 주소에 해당하는 파일이 **따로 없다.** 캐시에 없으니 `undefined` 가 나가고, `respondWith(undefined)` 는 그 요청을 그냥 깨뜨린다 — 홈 화면에 추가해둔 앱을 비행기 모드에서 열면 안 떴다.

**고침** — 주소로 들어온 화면(`navigate`)이면 `/index.html` 로 돌린다. 돌려줄 것이 없으면 `Response.error()` 로 「네트워크 실패」를 분명히 알린다.

### M-3 · 서비스 워커가 남의 집 응답까지 캐시했다 — 낮음

운동 검색(wger.de) · 날씨 응답까지 담아뒀다. 캐시가 계속 부풀고 옛 결과가 되살아난다. 이제 우리 집(`type === 'basic'`) 것만 담는다.

### M-4 · 물음 창이 겹치면 기다리던 쪽이 영영 멈췄다 — 보통

`confirmDialog()` 는 promise 를 돌려준다. 이미 열려 있는데 또 부르면 `setState(next)` 가 앞의 것을 **덮어썼다.** 앞의 물음은 화면에서 사라지고 그 promise 는 영영 안 풀린다 — 그것을 `await` 하던 코드가 그 자리에서 멈춘다. 덮어쓰지 않고 줄을 세운다.

## 훑었지만 손대지 않은 것

이미 단단해서 고칠 것이 없었다.

- **원판 피하기**(`PlateDodge.jsx`, 1,200줄) — `visibilitychange` · `pagehide` · 포인터/키 정리까지 되어 있다
- **파칭코 티켓 회계** — 시작 시점 확정 차감, 이탈 시 정산이 문서화되어 있다 ([BUGS.md](BUGS.md))
- **욕설 누적**(`db.countAbuse`) — 짜증(`mild`)과 되돌린 것(`dismissed`)을 이미 제외한다
- **측정 저장 검증**(`routes/measures.js`) — 타입 · 날짜 · 크기 전부 막는다
- **소유권 확인** — 운동 · 인바디 · 측정 · 루틴 · 제보 모두 `id + user_id` 로 찾는다. 남의 것에 손댈 길이 없다
- **`safeStorage`** — 쿠키를 막아둔 브라우저에서 던지는 경우까지 감싸져 있다
