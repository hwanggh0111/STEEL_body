# 리메이크 대상 — 전체 훑기 (2026-09-02)

앱의 화면을 전부 훑어 **다시 짜야 할 곳**을 뽑았다.

「리메이크」는 **화면을 새로 짜는 것**이다. 버그 고치기로 좁게 잡지 않는다 —
무엇을 먼저 보여줄지, 무엇을 묶고 무엇을 나눌지, 사람이 여기 온 이유가 무엇인지를
다시 정하는 일이다.

## 이미 한 것 (다시 안 본다)

| 날짜 | 다시 짠 화면 |
|---|---|
| 8/26 | 홈 · 관리자 · 고객센터 · 기록 · 인바디 · 로그인 · 회원가입 · 운동 알림 · 공지함 · 껍데기(Layout · TabBar) |
| 8/28 | 히스토리 (목록 → 달력) |
| 8/31 | 측정 시스템 (옆으로 밀리던 탭 일곱 → 격자) |
| 9/1 | 관리자 「AI 관리자」 · 관리자 「해킹 보안」 · 운동 검색(부품 분리) |
| 9/2 | 기능성운동(옛 홈트레이닝) 고르는 화면 |

## 뽑은 방법

화면 파일을 줄 수로 세우고, **머리 주석이 없는 것**부터 봤다. 이 저장소는 화면을 다시
짤 때마다 그 위에 왜 그렇게 했는지를 적어둔다 — 주석이 없는 화면은 **한 번도 다시 안 본
화면**이다. 그다음 각 화면에서 「사람이 여기 온 이유」와 「화면이 실제로 주는 것」이
어긋나는 자리를 찾았다.

# 1순위 · 비교 화면 (`pages/ComparePage.jsx` · 388줄)

**한 번도 다시 안 본 화면이다.** 머리 주석이 없는 두 화면 중 하나다.

## 1-1. 같은 화면 안에서 규칙 둘이 싸운다 — 제일 큰 것

8/25 에 **「몸에 등급을 매기지 않는다」**고 정했다. 그래서 `DiffValue` 는 늘고 줆에
좋고 나쁨을 안 붙이고 **방향만** 색으로 나눈다. 주석에도 그렇게 적혀 있다.

그런데 **그 바로 아래 「종합 평가」가 등급을 매긴다.**

| 종합 평가가 지금 하는 말 | 색 |
|---|---|
| 체중 2.0kg 증가 | 주황 (warning) |
| 체지방률 1.5% 증가 | 빨강 (danger) |
| 골격근 0.8kg 감소 | 빨강 (danger) |
| 체중 3.0kg 감량 | 초록 (success) |

**벌크업 중인 사람에게 「체중 증가」를 경고색으로 준다.** 위쪽 표는 같은 숫자를
아무 판단 없이 그리고, 아래 카드는 그것을 잘못이라고 말한다. 한 화면이 두 말을 한다.

## 1-2. 같은 다섯 숫자를 세 번 그리고, 그중 하나가 변화를 뭉갠다

표 · 묶음 막대 · 오각형이 같은 다섯 숫자를 그린다. 그중 **묶음 막대**가
체중(73) · 골격근(33) · 체지방(16) · BMI(23.5) · 체수분(41)을 **0부터 시작하는 한
눈금**에 세운다. 0부터 시작하는 공통 축은 **같은 단위끼리일 때만** 맞다 — 73짜리
눈금에서 체지방 1.5% 변화는 픽셀 두어 개다. **사람이 보러 온 바로 그 변화를 그림이
뭉갠다.**

> **처음에 오각형을 범인으로 적었다가 코드를 열어보고 바꿨다.** 오각형(`charts/Radar.jsx`)은
> **축마다 눈금이 따로**고 그 사실을 그림에 적어둔다 — 단위가 달라도 서로 안 뭉갠다.
> 한 축에 겹치는 것은 막대 쪽이었다. 이름만 틀렸다: 「밸런스 비교」는 균형을 재는
> 그림이라는 뜻인데 그런 그림이 아니다.

## 1-3. 과거와 현재를 거꾸로 고를 수 있다

날짜 고르는 칸 둘이 서로를 안 본다. **BEFORE 에 최신을, AFTER 에 옛날을** 골라도
막지 않고, 같은 날짜를 둘 다 골라도 그대로 그린다. 그러면 5kg 뺀 사람의 화면에
「체중 5kg 증가」가 뜬다.

## 1-4. 사진 비교와 숫자 비교가 서로 다른 날짜다

사진은 **전 · 후 한 장씩 고정**이고, 인바디는 **날짜를 골라서** 본다.
「3월 사진 vs 9월 사진」을 보면서 아래 숫자는 「6월 vs 7월」일 수 있다.
화면 이름이 「비교」인데 **두 비교가 서로 모른다.**

## 1-5. 다섯 덩어리가 순서 없이 쌓여 있다

사진 비교 → 상세 비교 → 종합 평가 → 과거 vs 현재 → 밸런스 비교.
무엇을 먼저 보라는 말이 없고, 위의 표와 아래 그래프가 **같은 숫자를 두 번** 그린다.

## 곁들여 남은 것

**사진 줄이기(`data/shrinkImage.js`)는 아직 브라우저로 못 봤다.** node 에는 캔버스가
없어 검사로 못 돌린다 — 폰 사진(3MB 이상)으로 한 번 올려봐야 한다. 이 화면을 다시
짜면서 같이 본다.

## 2-1. 서버 설정을 늘어놓기만 한다 — 9/1 에 AI 관리자에서 고친 그 문제

JWT 만료시간 · 알고리즘 · Rate Limit · Helmet · CORS · Body 크기 · Node 버전을

## 2-2. 사람 목록이 폰에서 옆으로 밀리는 표다

ID · 이메일 · 닉네임 · 역할 · 가입일 · 관리 **여섯 칸짜리 표**를 가로 스크롤로 둔다.

# 순서를 이렇게 잡은 이유

1. **비교** — 앱이 **틀린 말을 하는** 유일한 자리다. 화면이 못생긴 것보다 나쁘다.
   벌크업 중인 사람에게 「체중 증가」를 경고색으로 주는 것은 판단이지 모양이 아니다.
2. **보안 관리** — 관리자가 **판단을 못 하는** 자리다. 사람은 안 보지만 운영이 걸린다.
3. **측정 셋** — 쓰는 사람이 있는데 **쓸모가 반만** 나온다.
4. **제보함 · 루틴** — 지금도 되긴 된다. 큰 파일이라 시간이 든다.

# 1순위 — 한 것 (2026-09-02)

비교 화면을 다시 짰다. 덩어리 다섯을 **셋**으로 줄였다 —
**언제와 언제를 고른다 → 사진 → 얼마나 달라졌나(표 + 오각형).**

| 무엇 | 어떻게 |
|---|---|
| 「종합 평가」가 등급을 매기던 것 | **걷어냈다.** 무엇이 어느 쪽으로 갔는지만 적고, 그렇게 한다고 화면에 적었다 |
| 거꾸로 고를 수 있던 것 | 막지 않고 **알아서 앞뒤를 맞춘다**(`orderPick`). 바꿔 놓았다고 말해준다 |
| 얼마 만인지 없던 것 | 고른 두 날짜 사이를 적는다 (「84일 사이」 · 「4개월 사이」) |
| 사진과 숫자가 서로 모르던 것 | 사진에 **언제 올린 것인지**를 적고, 고른 날짜와 별개라고 적는다. 날짜를 지어내지 않았다 |
| 같은 숫자를 세 번 그리던 것 | **묶음 막대를 뺐다**(`charts/Bars.jsx` 도 지웠다). 표 + 오각형만 남긴다 |
| 「밸런스 비교」라는 이름 | 「한눈에 — 두 시점의 차이」로. 균형을 재는 그림이 아니다 |

계산은 `data/compare.js` 로 떼어냈다. **이 화면은 눈으로 봐서는 틀린 것을 못 잡는다** —
거꾸로 골라도 그래프는 멀쩡히 그려지고 숫자만 조용히 반대로 말한다. 그래서
`npm run check` 가 열다섯 가지를 돌려본다.

## 고치다 나온 것 — 검사의 주석 지우개에 구멍이 있었다

검사가 「주석은 빼고 코드만 본다」고 할 때 쓰던 `codeOf` 가 `/*` 를 만나면 무조건
주석 시작으로 봤다. 그런데 비교 화면에 **`accept="image/*"`** 가 있다 —
거기서부터 다음 `*/` 까지 **코드 4천 자가 통째로 사라졌다.** 이모지 검사가 이 화면의
4천 자를 여태 안 보고 있었다. `/*` 앞에 공백이나 `{` 가 있을 때만 주석으로 보게 고쳤다.

**사진 줄이기는 아직 브라우저로 못 봤다.** 폰 사진(3MB 이상)으로 한 번 올려봐야 한다.
