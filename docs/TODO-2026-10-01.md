## 1. 구글 로그인 켜기

**코드는 다 돼 있다. 남은 것은 열쇠뿐이다.** 절차는 `docs/google-login-setup.md` 에
그대로 있고, 오늘(9/30) 다시 읽어 **지금도 맞는 것을 확인했다.**

### 요점만

1. <https://console.cloud.google.com/apis/credentials> 에서 프로젝트 → OAuth 동의 화면
   (외부 · 범위는 `email`, `profile` 둘) → **OAuth 클라이언트 ID(웹)**
2. **승인된 리디렉션 URI** — 한 글자도 다르면 `redirect_uri_mismatch` 로 막힌다

   | 언제 | 넣을 주소 |
   |---|---|
   | 내 컴퓨터 | `http://localhost:4000/api/oauth/google/callback` |
   | 배포한 뒤 | `https://<배포주소>/api/oauth/google/callback` |

   **화면(5173)이 아니라 서버(4000)** 다.
3. `backend/.env` 에 두 줄 (이 파일은 git 에 안 올라간다)

   ```
   GOOGLE_CLIENT_ID=...
   GOOGLE_CLIENT_SECRET=...
   ```
4. 테스트 상태로 두면 **테스트 사용자에 넣은 계정만** 들어온다 — 본인 계정을 넣어둔다

### 됐는지 어떻게 아나

- 서버를 다시 띄우면 `[oauth] 소셜 로그인 열쇠가…` 줄이 **사라진다**
- `GET /api/oauth/providers` 가 `google: true`
- 로그인 · 회원가입 화면에 **구글 단추가 나타난다** (열쇠가 없으면 아예 안 그린다)
- `cd backend && npm run oauth` — 가짜 구글로 한 바퀴. **열쇠 없이도 도는 검사**라
  지금도 통과한다(오늘 확인). 열쇠를 넣은 뒤에는 **진짜로 한 번 눌러보는 것**이 남는다

> **폰 테스트(`scripts/phone-test.ps1`)에서 구글은 대개 막힌다.** 터널 주소가 열 때마다
> 바뀌고 구글은 등록된 주소로만 돌려보낸다. **폰에서는 이메일 로그인으로 확인**하고
> 구글은 PC 에서 보는 것이 제일 간단하다.

## 2. 열쇠 발급 — 셋

없으면 **그 기능만 조용히 빠진다.** 서버가 뜰 때마다 스스로 말한다.

| 열쇠 | 없으면 지금 무슨 일이 | 어디서 | 어디에 |
|---|---|---|---|
| **GOOGLE_CLIENT_ID / SECRET** | 구글 단추가 안 나온다 | Google Cloud Console | `backend/.env` + Render |
| **VAPID (PUBLIC / PRIVATE)** | 운동 알림이 **안 나간다.** 설정함 줄이 「서버가 아직 못 보내요」로 뜬다(9/30 에 그렇게 고쳤다) | `npx web-push generate-vapid-keys` — **직접 만든다. 발급받을 데가 없다** | `backend/.env` + Render |
| **SMTP_HOST / USER / PASS** | **비밀번호 찾기만** 막힌다 (가입은 그대로 된다 — 아래 참고) | 지메일이면 앱 비밀번호 | `backend/.env` + Render |

- **Render 에도 같은 값을 넣어야 한다.** `.env` 는 내 컴퓨터 것이다.
- `backend/.env.example` 에 들어갈 자리가 다 적혀 있다 (그 파일은 자리표뿐이라 git 에 있다).
- VAPID 는 **한 번 만들면 바꾸지 않는다** — 바꾸면 이미 켜둔 사람의 구독이 전부 죽는다.

## 3. 로그인 · 회원가입 싹 훑기

### 오늘 미리 봐서 **이미 단단한 것** (내일 다시 볼 필요 없다)

- **계정은 이메일 하나로 이어진다.** 이메일로 가입한 뒤 구글로 들어와도 **계정이
  갈라지지 않는다**(`findUserByEmail`).
- 구글이 **「확인 안 된 메일」이라고 하면 막고**, 메일을 아예 안 주면 **계정을 안 만든다**
  (그 둘을 안 막으면 남의 기록으로 들어가는 길이 된다).
- 소셜 실패 문구가 **종류별로** 다르다 — 준비 중(`not_configured`) · 메일 미확인 ·
  메일 미제공 · 링크 만료(`invalid_state`). 「다시 시도해주세요」로 뭉개지 않는다.
- **가입 규칙이 화면과 서버에서 같다** — 아이디 `4~20자`(영문·숫자·`!@#$%^&*._-`),
  비밀번호 `8자 이상 + 영문 + 숫자`, 닉네임 `30자`(칸에 `maxLength` 도 걸려 있다).
- **세션이 끊길 때 까닭을 알린다** — 9/30 에 고쳤다(그 전에는 세 자리 중 한 자리에만
  쪽지가 있었다).
- 계정 삭제는 **30일 유예**이고 그 안에 로그인하면 되살아난다. 구글로 들어와도 되살아난다.

### 내일 볼 자리 — 짚어둔 것 다섯

1. **인증번호가 램에 있다.** `authRoutes` 의 저장소가 메모리라 **서버가 다시 뜨면
   사라진다.** Render 무료 판은 잠들었다 깨므로, 비밀번호 재설정 중에 깨어나면
   「인증번호를 먼저 발송해주세요」로 떨어진다. → 어디에 둘지 정해야 한다.
2. **구글로만 가입한 사람은 이메일 로그인을 못 한다.** 그때 비밀번호는 **무작위**로
   만들어진다(`randomBytes`). 그래서 들어올 길이 구글 하나뿐인데, 구글이 막히면
   비밀번호 찾기를 거쳐야 하고 그것은 **SMTP 가 있어야** 된다. 2번이 이걸 닫는다.
3. **아이디를 고칠 자리가 없다.** 구글로 만들어진 아이디는 `google_1a2b3c4d` 같은
   무작위다 — 설정함에서 닉네임은 고치는데 아이디는 못 고친다. 고치게 할지 정해야 한다.
4. **SMTP 가 없을 때 「비밀번호 찾기」 화면이 미리 말해주는가.** 지금은 눌러서 보내봐야
   안다(서버는 「일시적으로 비활성화됐어요」라고 답한다). 설정함의 운동 알림 줄을
   9/30 에 고친 것과 **같은 종류**다 — 막힌 것을 눌러보기 전에 알려주는 쪽이 맞다.
5. **자동 로그인 · 스플래시 흐름.** 쿠키/토큰이 있으면 `/auth/me` 로 검증하고 들어간다.
   열쇠를 넣고 구글로 들어온 뒤 그 길이 어떻게 섞이는지 한 번 눌러봐야 안다.
