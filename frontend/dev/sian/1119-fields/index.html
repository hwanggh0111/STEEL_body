기록 칸의 숫자가 좁은 폰에서 안 보인다 — 시안 넷 · 11/19

먼저 버그다. 「지금」 틀을 320 폭으로 보면 무게 칸이 비어 보인다 — 적어둔 100.5 가 거기 있는데 글 자리가 2.7px 라 안 보이는 것이다. ± 단추 둘(36+36)과 틈(4+4)이 칸에서 먼저 자리를 가져간다. 상수는 전부 코드에서 읽어 셌다 (--padding-x: 20 · .card{padding:16} · minmax(0,1.35fr) minmax(0,0.8fr) minmax(0,1.35fr) gap 8 · NumberStep width:36).

글자 폭은 어림이 아니라 글꼴 파일에서 읽은 값이다 — Barlow 400 의 숫자는 527/1000 em, 마침표 278 이고 font-variant-numeric: tabular-nums 가 전역이라 숫자는 모두 같은 폭이다(14px 에서 숫자 7.378px · 마침표 3.892px). 그래서 「22.5」 = 26.0px · 「100.5」 = 33.4px 다. 빼는 것의 합은 86 — ± 단추 72 + 틈 8 + 칸 안 여백 4 + 테두리 2 다 (칸 안 여백은 .input 의 14 가 아니라 NumberStep 이 인라인으로 덮는 2 다).

뿌리는 ± 가 아니다. 320 에서 단추를 28 로 깎고 칸 안 여백을 0 으로 해도 25.5px 라 「100.5」가 안 든다. 깎기는 390 만 겨우 살리는 임시방편이고, 글자를 150% 로 쓰면 다시 무너진다 — 길은 좁은 폭에서 줄을 쪼개는 것이다.

A · 줄만 바꾼다좁으면 두 줄 · 글 자리 33 → 41px (± 32)
가장 작은 고침이고 넓은 화면은 지금 그대로다. 두 칸은 세 칸보다 넓다 — 글 자리 33(320) · 53(360) · 68(390) · 88(430). 값 둘 — ⑴ 320 에서 「100.5」(33.4)에 0.4px 모자란다(± 를 32 로 줄이면 41 로 선다). ⑵ 폭을 숫자로 가르는 줄(420px)이 하나 생긴다 — 글자를 150% 로 쓰는 사람은 폭이 안 변하니 또 빠듯해진다.
B · 한 줄에 한 칸글 자리 160px
어떤 폰에서도, 글자 200% 에서도 안 잘린다. 값 — 세로가 세 줄로 길어져 적기 단추가 밀리고, 운동 중 손가락이 오가는 거리가 늘어난다.
C · 숫자는 전폭, ± 는 아래 좌우글 자리 216px · 과녁 100px 넘게
엄지가 닿는 자리(파란 띠) 안에 숫자와 ± 가 함께 들어온다 — 단추에 「− 2.5」처럼 얼마씩인지 적을 자리도 생긴다. 값 — 세로가 B 보다 더 길고 지금 꼴과 가장 많이 달라진다.
D · 스스로 줄을 바꾼다바닥을 calc(5ch + 88px) 로 적어둔다
폭을 숫자로 가르지 않는 유일한 안. 한 칸의 바닥을 「숫자 다섯 자 + ± 자리」로 적어두면 모자란 폰에서 알아서 줄이 바뀌고, 글자를 150% 로 쓰면 ch 도 같이 자라 그때도 맞는다. 값 — 줄 수가 폰마다 달라 화면이 어떻게 설지 한눈에 못 그린다.
