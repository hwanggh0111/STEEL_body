4. 걷은 거짓 (여섯) — 의심이었지만 재 보니 아니었다

  • Postgres 쓰기 실패를 다시 안 한다 → 한다. storage.write 가 실패를 돌려주고(11/23) _flush 의 catch 가 _dirty 를 세우고 finally 가 500ms 뒤를 건다. 다음 쓰기가 없어도 혼자 다시 쓴다 — 자가 쓰기에 실패를 먹여 확인했다(글로만 적어두면 그 손이 사라지는 날 모른다)
  • /send-code 마다 시도 수가 처음으로 돌아간다 → 맞지만 IP 자가 막는다 (verifyCode 15분에 10회 · authCode 분당 3회). 번호 백만 개를 10회씩으로는 못 뚫는다
  • 확인창이 StrictMode 에서 두 번 들어간다 → 그 자리는 진짜였고 고쳤다(위 표). 다만 「개발에서만」이 아니다 — 줄에 둘 이상 쌓인 채 다시 마운트되면 운영에서도 난다
  • 분모 0 후보 셋(검사소 READ) → 닿지 않는다. niceScale 은 max > min 을 먼저 막고, rmsOf 의 버퍼 길이는 0 이 될 수 없다. 다만 niceScale 은 값 차이가 극히 작으면 눈금 셈이 멎는다 — 인바디·무게 테두리가 그 값을 막고 있어 지금은 못 닿는다(전제가 깨지는 날을 적어둔다)
  • 배포 뒤 흰 화면(옛 껍데기가 없는 조각을 조른다) → 회복 손이 이미 있다. ErrorBoundary 가 조각 오류를 알아보고 한 번만 새로 받는다(sessionStorage 표로 고리를 막는다)
  • 옛 서비스워커가 옛 화면을 붙든다 → CACHE_NAME 이 빌드마다 바뀌고 새 워커가 옛 캐시를 지운다. 담아둔 조각도 읽을 때 종류를 본다(11/11 에 세운 자) — HTML 이 .js 자리에 담겼던 그 꼴은 스스로 낫는다
